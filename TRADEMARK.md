# NoClass™ Trademark Policy

This policy explains how the NoClass™ name, logo, and related branding may be used.

The NoClass™ core source code is licensed under the Apache License, Version 2.0.
However, the Apache License does not grant unrestricted rights to use the
NoClass™ name, logo, visual identity, or related branding.

NoClass™ is a trademark of Danny Mbanginu for software framework,
developer-tool, documentation, and related technology use.

The NoClass™ name and identity are important because they help users identify
the official project.

## 1. Protected Names and Branding

This policy applies to:

- NoClass™
- NoClass
- NoClass PHP Procedural Framework
- NoClass™ PHP Procedural Framework
- The NoClass™ logo
- Official NoClass™ artwork
- Official NoClass™ website branding
- Official NoClass™ documentation branding
- Any confusingly similar name or branding used to suggest official association with NoClass™

## 2. General Rule

You may use the NoClass™ name to truthfully describe the original project,
compatibility with the project, or the origin of software based on the project.

You may not use the NoClass™ name, logo, or branding in a way that suggests
your project, product, service, fork, package, company, or website is officially
approved, maintained, sponsored, certified, or endorsed by the NoClass™ project
unless you have written permission.

## 3. Allowed Uses

You may use the NoClass™ name in accurate descriptive statements such as:

Built with NoClass™.
Compatible with NoClass™.
A module for NoClass™.
A fork of NoClass™.
Based on NoClass™.
Uses the NoClass™ PHP Procedural Framework.

You may also use the NoClass™ name when writing articles, tutorials, reviews,
videos, documentation, or educational material about the framework, provided
that the use is accurate and not misleading.

## 4. Forks

You are allowed to fork the NoClass™ code under the terms of the Apache License,
Version 2.0.

However, if you distribute a modified version, you must make it clear that your
version is a fork or modified version.

Acceptable examples:

MyFramework, based on NoClass™
ExampleCMS, powered by a modified version of NoClass™
NoClass™ Community Fork
NoClass™ Experimental Fork

Unacceptable examples unless authorised:

Official NoClass™
NoClass™ Pro
NoClass™ Enterprise
NoClass™ Framework Official
Danny's Official NoClass™

## 5. Modified Versions

If you distribute a modified version of NoClass™, you must not present it as the
official NoClass™ release.

You should clearly state that changes were made.

Example:

This project is based on NoClass™ and includes modifications that are not part
of the official NoClass™ release.

## 6. Logo Use

You may not use the official NoClass™ logo in your product, website, package,
marketing material, or fork in a way that suggests official endorsement.

You may use the logo in educational or descriptive content, such as an article,
tutorial, review, or video, provided the use is accurate and not misleading.

Do not alter the NoClass™ logo and present it as official branding.

## 7. Domain Names and Social Media

Do not register domain names, social media accounts, package names, organisation
names, or community names that could mislead users into believing they are
official NoClass™ resources.

Examples that should not be used without permission:

officialnoclass.com
noclass-framework-official.com
github.com/official-noclass
NoClassOfficial
NoClassEnterprise

Acceptable independent examples may include names that clearly show separation:

noclass-tutorials.example
my-noclass-examples
noclass-community-notes

## 8. Packages, Modules, and Extensions

If you create a package, module, plugin, helper, or integration for NoClass™,
you may describe it as being for NoClass™.

Good examples:

Blog module for NoClass™
NoClass™ Redis integration
NoClass-compatible auth helper

Avoid names that suggest official status unless approved:

Official NoClass™ Auth
NoClass™ Core Auth
NoClass™ Enterprise Auth

## 9. Commercial Use

You may use NoClass™ commercially under the Apache License, Version 2.0.

You may offer hosting, support, consulting, training, or development services
around NoClass™.

However, you must not imply that your commercial service is officially provided,
certified, sponsored, or endorsed by the NoClass™ project unless you have written
permission.

Acceptable:

We provide consulting for applications built with NoClass™.

The following examples are reserved for official NoClass™ project use or
written authorisation by the trademark owner:

* NoClass™ Enterprise
* NoClass™ Enterprise Edition
* NoClass™ Professional
* NoClass™ Pro
* Official NoClass™ Support
* Official NoClass™ Hosting
* Certified NoClass™ Partner


## 10. Merchandise and Non-Software Goods

The NoClass™ project branding is intended for software framework,
developer-tool, documentation, education, and related technology use.

Do not use the NoClass™ name or logo for clothing, footwear, merchandise, or
unrelated physical goods in a way that suggests official association with the
NoClass™ project unless you have written permission.

## 11. Attribution

When referring to NoClass™, please use clear attribution where practical:

NoClass™ was originally created by Danny Mbanginu.

or:

NoClass™ PHP Procedural Framework is an open-source procedural PHP MVC framework
originally created by Danny Mbanginu.

## 12. Reporting Misuse

If you believe someone is misusing the NoClass™ name, logo, or branding, please
contact the project owner or maintainers.

For permission to use the NoClass™ name or logo in a way not covered by this
policy, contact the project owner or maintainers.

Permission may be granted, denied, limited, or withdrawn depending on the
situation.
